# November feature batch

Implemented in source; server deployment and signed app installation are separate.

- **Request a song (Add tab):** debounced iTunes song-catalog search with recording-specific artwork and album labels. Library matches disable requests; selected missing tracks use the existing authenticated reports API and shared wanted list. Repeat taps are disabled after success. Requests do not download songs. Shared wanted artwork uses the existing exact metadata lookup. Unicode identities are retained, fixing collisions between unrelated non-Latin artists.
- **Endless Next:** uses new library recommendations, then cycles playable songs when the finite library is exhausted. Avoids an immediate repeat when alternatives exist. Continuation retains at most 20 history and 20 upcoming tracks. Explicitly selected playlists keep their original size until continuation. Rapid skips still replace pending loads. Offline skips consider saved/boosted songs; playback cannot continue without any playable files.
- **Playlist glow:** two accent colors surround playlist covers and playlist icon tiles, including Spotify imports and custom pictures. Imported playlist detail also receives its songs for mosaic artwork.
- **Search:** existing local typo tolerance remains, with full-width character folding added. The explicit “Find by lyrics or translated title” action asks the assistant to identify the recording through web evidence, then matches library copies and offers requests for missing songs. It does not interrupt instant local search. Identification is approximate and depends on the configured model/search provider; it is not an offline translation engine.
- **Ask Yomi web search:** bounded `web_search` tool through Brave Search, sharing the six-tool chat budget. Fixed provider URL, bounded response size, validated HTTP(S) source links, no listener credentials sent to the provider. Errors are distinct from empty results. Returned source links appear in chat and identification results.
- **Volume boost:** song three-dot menu → Volume boost → Off / +3 / +6 dB. The authenticated server renders a separate MP3 using ffmpeg gain and peak limiting. Original audio is unchanged. Applies per song for the current session; preparing the copy requires connectivity. Boosted copies can subsequently play offline, are separate from permanent downloads, and are cleaned up on player disposal. Two server rendering jobs maximum, two-minute rendering deadline. Native/system volume stays separate.
- **Alternate icons:** Default, Midnight and Sakura in Settings → Appearance. iOS uses bundled alternate app icons, Android uses launcher aliases, and macOS changes the running Dock icon (not the installed Finder bundle icon). macOS selection persists between launches. Device launcher behavior still needs a physical-device check. Vector/code-native artwork is reproducible using `swift app/scripts/generate_alternate_icons.swift` from the repo root.

## Server configuration

Deploy the updated Go service for web tools and volume boost:

- Keep existing `YOMI_LLM_KEY`, `YOMI_LLM_URL`, and `YOMI_LLM_MODEL` configuration.
- Set `YOMI_SEARCH_KEY` to a Brave Search API key. With no key, the assistant explicitly reports web search unavailable.
- Install `ffmpeg` on the service PATH with `libmp3lame` support for volume boost. Without it the menu reports that boost could not be prepared. The server also needs its existing song-path resolver and access to the original music files.
- Catalog requests reuse existing reports; no new database or catalog API key is needed. Catalog availability and coverage depend on iTunes.

Provider references: [Apple Search API](https://developer.apple.com/library/archive/documentation/AudioVideo/Conceptual/iTuneSearchAPI/index.html), [Brave web search](https://api-dashboard.search.brave.com/api-reference/web/search/get).
